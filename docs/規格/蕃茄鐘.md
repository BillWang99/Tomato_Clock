# 蕃茄鐘
最後核對：2026-10-24（對應版本 66395f2）
程式範圍：src/、push-worker/（推播伺服器）
相關規則：CLAUDE.md §0

## 概要

像素風格的網頁蕃茄鐘，Vite + Vue 3 + TypeScript 的單頁靜態網站，發佈在 GitHub Pages（https://billwang99.github.io/Tomato_Clock/）。沒有帳號，所有設定與紀錄只存在使用者瀏覽器的 localStorage。唯一的後端是選用的推播小伺服器（Cloudflare Worker，見「鎖螢幕推播」），只在使用者打開「鎖螢幕也提醒」時用到，伺服器掛掉也不影響計時。

## 程式分層

| 層 | 位置 | 負責 |
|---|---|---|
| 核心（純函式） | `src/core/` | 計時狀態機、設定檢查、今日統計、點陣字與蕃茄點陣圖、文案；不碰畫面與瀏覽器 API |
| 共用邏輯 | `src/composables/` | 把核心接上 Vue：現在時間、存檔、聲音、螢幕常亮、分頁標題、時間鍵盤要改哪個時長 |
| 通用元件 | `src/components/base/` | 像素按鈕、點陣數字、步進器、時長欄、開關、面板、對話框；不知道蕃茄鐘業務 |
| 業務元件 | `src/components/business/` | 模式分頁、蕃茄主角、倒數、輪次、控制列、設定、統計、碎片、時間到橫幅、時間鍵盤 |

## 計時規則

- 三種階段：專注（預設 25:00）、短休息（5:00）、長休息（15:00）。時長可以設到秒，範圍 00:01～99:59。
- 專注完成後，本輪累積到「長休息間隔」（預設 4）個就接長休息，否則接短休息；休息完回到專注。
- 離開長休息（休完、跳過、手動切走）都會開始新的一輪。
- 跳過、手動切換分頁都不算完成，不加蕃茄數。
- 計時以「結束時間戳記」計算：切到背景、鎖螢幕、重新整理後回來，剩餘時間仍然正確。
- 時間到時，下一段從「發現時間到的那一刻」起算（不從原本的結束時間起算）。
- 「自動開始下一段」關閉時，下一段停在未開始；開啟時立刻開始。
- 改設定只影響還沒開始的這一段；進行中或暫停中的不受影響，統計記實際跑的長度。

## 鎖螢幕推播

- 設定「鎖螢幕也提醒」預設關閉。打開時才詢問通知權限並訂閱推播；任何支援推播的瀏覽器都能用（iPhone 必須從主畫面打開，16.4 以上）。
- 顯示規則：伺服器沒設定或瀏覽器不支援 → 不顯示；iPhone 在 Safari 分頁裡 → 顯示「先加入主畫面」；拒絕過通知 → 顯示到系統設定開啟。
- 開始／繼續計時時，App 請伺服器「N 毫秒後提醒」，用伺服器時間算發送時刻（不相信手機時鐘）；編號是這段計時的結束時間戳記。
- 暫停、重設、跳過、切換模式、App 開著時自己發現時間到 → 取消。排程的編號在**送出前**就記住（請求到了但回應遺失也能取消）；取消失敗（斷網）會留著編號，下次狀態改變時再取消。
- 伺服器回 410（推播服務說訂閱已失效）→ App 自動退訂、重新訂閱，用新的推播位址再排一次。
- 自動開始下一段時，新的提醒直接取代舊的。
- 推播失敗只在設定面板顯示一行說明，計時與畫面上的提醒完全不受影響。
- 通知文字由伺服器依階段產生（「🍅 專注完成！休息一下吧」等），聲音是系統預設提示音；推播 5 分鐘內送不到就丟掉。
- 伺服器（`push-worker/`）：
  - `POST /api/schedule`、`POST /api/cancel`、`GET /api/health`，不用登入。
  - 每個推播訂閱一個 Durable Object，最多一筆待發提醒，用 alarm 準時醒來；發完、取消、訂閱失效都立刻刪資料。訂閱失效時只留一個「已失效」記號（不含訂閱資料），下次排程回 410 讓 App 重新訂閱。
  - alarm 醒來時若提醒還沒到時間就不發、把鬧鐘調回去；發送途中如果 App 排了新提醒，發完只刪舊的那筆。金鑰不對導致加密失敗時不重試、直接刪除。
  - 只對 Apple／Google／Mozilla／微軟的推播服務網址發請求；訂閱金鑰實際解碼檢查（公鑰 65 bytes、驗證密鑰 16 bytes）；提醒限 1 秒～100 分鐘；請求內容上限 4 KB（宣告超過直接 413）。
  - 頻率限制：同一個 IPv4 位址、或同一個 IPv6 /64 網段，每分鐘 30 次。
  - 來源（CORS）只允許網站網址，但這只擋得住別的網頁，擋不住自己寫程式呼叫；真正的防護是上面的白名單、固定文字與頻率限制。
  - 網站用 `text/plain` 送 JSON（簡單請求），不用每次多一個預檢請求。
  - 加密 RFC 8291 `aes128gcm`、驗證 RFC 8292 `vapid`（`@block65/webcrypto-web-push`），Apple 只收這兩種。
  - 不開請求日誌。VAPID 私鑰只存在 Worker secret（`VAPID_PRIVATE_KEY`），公鑰在 `wrangler.jsonc` 與 `src/core/pushConfig.ts`。
- 費用：Cloudflare 免費方案，超過每日額度當天就不發推播，不會產生費用。

## 修改時長

- 設定面板每個時長一列：`−` 減 1 分鐘、中間的 `MM:SS` 點一下開時間鍵盤、`+` 加 1 分鐘。
- 還沒開始時，點畫面中央的大數字也會開時間鍵盤，改的是目前這個模式的時長。計時中、暫停中不能點。
- 時間鍵盤像微波爐：數字從右邊推進來，最後兩位是秒。從 25:00 按 5、0、3、0 → 50:30。打開時第一個按的數字會取代原本的時間。
- 秒數可以打超過 59（例如 00:90），確定時換算成 1 分 30 秒；00:00 與超過 99:59 不能確定。
- 有 05:00、15:00、25:00、50:00 四個快捷鍵；電腦上可直接用鍵盤打數字、Backspace 刪除、Enter 確定、Esc 取消。
- 設定改了就自動存進 localStorage，重新整理或下次打開都還在。

## 時間到的提示

- 畫面：上方黃色橫幅（按「知道了」或任何操作後消失）、全畫面閃三下、專注完成時蕃茄跳一下並噴出像素碎片。
- 分頁標題變成「⏰ 時間到！」。
- 聲音：Web Audio 即時合成 8-bit 音效；Android 另外震動。
- 已知限制（2026-10-23 已確認接受）：iOS 鎖螢幕或切到別的 App 時網頁被暫停，時間到那一刻不會響；**加到主畫面的 PWA 也一樣**（iOS 不讓網頁在背景執行，也沒有「預約本機通知」的功能）。回到網頁時立刻顯示橫幅，提示音在使用者下一次點畫面時補播。設定裡的「計時中螢幕常亮」可避免手機自動鎖定（主畫面 App 需要 iOS 18.4 以上才支援）。2026-10-24 起可在設定打開「鎖螢幕也提醒」改用伺服器推播，見下一節。

## 字型與圖示

- 中文像素字型：Fusion Pixel Font 12px（SIL OFL 1.1，授權檔 `src/assets/fonts/OFL-fusion-pixel.txt`），只保留介面用到的字。
- **改了介面文字（新增中文字）後要重跑** `node scripts/subset-font.mjs <完整字型.woff2>`，否則新字會用系統字型顯示。
- 計時數字是自己畫的 5×7 點陣字（`src/core/pixelFont.ts`），不靠字型。
- 圖示由 `npm run icons`（`scripts/make-icons.mjs`）產生到 `public/icons/`：專門畫的 20×19 大頭蕃茄（大眼睛加反光、腮紅、ω 小嘴、捲捲的蒂頭），奶油黃底加三顆粉色小星星；maskable 版縮在中間安全區域、不放星星。分頁小圖示（favicon.svg）是同一顆蕃茄、透明底。
- iOS 會快取主畫面圖示：換圖示後，已經加到主畫面的人要刪掉再重新加入才會看到新圖示。

## PWA（離線與安裝）

- 用 `vite-plugin-pwa` 產生 Service Worker，建置時把所有檔案（HTML、JS、CSS、字型、圖示、manifest）預先快取，第一次打開後就能離線使用。
- 有新版時 Service Worker 在背景下載，**下次打開**才換成新版；計時狀態存在 localStorage，換版不會中斷計時。
- 加到主畫面：iPhone 用 Safari 分享 →「加入主畫面」；Android Chrome 會出現安裝提示或在選單裡「安裝應用程式」。
- 不含推播通知（鎖屏提醒仍是已知限制，見上方）。
- **退版注意**：裝過 Service Worker 的使用者會一直用快取的版本。退版時不能直接部署沒有 PWA 外掛的舊版建置（舊網站沒有 `sw.js`，已註冊的 Service Worker 不會被移除），要用保留 PWA 外掛的版本，或設定 `selfDestroying: true` 把它移除。退到 v0.1.0 時，新版存成秒數的設定與今日統計舊版讀不到，會回到預設值與 0。

## 發佈

推上 `main` 後 GitHub Actions（`.github/workflows/deploy.yml`）依序執行 lint、測試、建置，通過才發佈到 GitHub Pages。repo 的 Settings → Pages → Source 必須設成「GitHub Actions」。

整個部署約 1.5 分鐘：排隊 30～60 秒、建置約 35 秒、發佈約 10 秒。

推播伺服器另外部署（`push-worker/`，`npx wrangler deploy`），網站的自動部署不會動到它。第一次部署前要：`npx wrangler login`、`npm run vapid` 產生金鑰、公鑰填進 `wrangler.jsonc` 與 `src/core/pushConfig.ts`、私鑰用 `npx wrangler secret put VAPID_PRIVATE_KEY` 存進 Cloudflare、Worker 網址填進 `src/core/pushConfig.ts`。兩個設定空著時，網站不會顯示推播開關。

推上去之後跑 `npm run verify:deploy`（或 `bstack verify-release`，它的健康檢查就是這支），一個指令做完：
1. 每 5 秒查一次這個 commit 的部署，失敗時列出失敗的步驟。
2. 部署成功後檢查首頁、sw.js、registerSW.js、manifest 與 index.html 引用的 JS／CSS 都回應 200。
3. 比對網站上的 JS／CSS 檔名與本機 `dist/` 相同，確認上線的就是這一版（需要先在本機 `npm run build`）。
