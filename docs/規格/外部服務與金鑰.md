# 外部服務與金鑰
最後核對：2026-10-24（對應版本 f23505e）
程式範圍：scripts/usage.mjs、scripts/rotate-vapid.mjs、push-worker/wrangler.jsonc、.github/workflows/deploy.yml
相關規則：CLAUDE.md §0

本專案秉持 **0 成本**：每個外部服務都停在免費方案，而且「超過額度 = 停止服務」，不會「超過額度 = 扣款」。repo 是 public，**裡面只有清冊，沒有任何秘密的值**。

## 0 成本守則

1. 每個外部服務只用免費方案，帳號**不綁付款方式**。沒綁付款方式就不可能被收費。
2. 不新增需要另外註冊或付費的服務（監控、錯誤追蹤、資料庫都不加）。要加之前先更新這份清冊。
3. repo 維持 public：GitHub Pages、Actions、Secret scanning 對 public repo 都免費。改 private 會需要 GitHub Pro（違反 0 成本）。
4. 用量用 `npm run usage` 看；超過免費額度 50% 提醒、80% 警告。80% 以上時指令結束代碼是 1，`bstack verify-release` 會判定失敗，提醒你處理。
5. 推播伺服器被灌請求時，先關總開關（見下方「緊急止血」），再查原因。

## 金鑰清冊

| 名稱 | 用途 | 存放位置 | 讀得回來嗎 | 備份 | 誰能換 |
|---|---|---|---|---|---|
| `VAPID_PRIVATE_KEY` | 推播簽章（秘密） | Cloudflare Worker secret | 不行（寫進去就讀不出來） | 你的密碼管理器 | 你（`npm run vapid:rotate`） |
| `VAPID_PUBLIC_KEY` | 推播公鑰（公開） | `push-worker/wrangler.jsonc`、`src/core/pushConfig.ts` | — | 在 repo 裡 | 同上，由腳本自動更新 |
| wrangler 登入授權 | 從你的電腦部署推播伺服器、讀用量 | `~/Library/Preferences/.wrangler/config/default.toml`（明文） | — | 不需要（隨時 `npx wrangler login` 重來） | 你 |
| GitHub 登入 | push 程式碼 | 你電腦的 git 認證 | — | 不需要 | 你 |

公開設定（不是秘密）：`VAPID_PUBLIC_KEY`、推播伺服器網址、`ALLOWED_ORIGINS`、`VAPID_SUBJECT`、`PUSH_ENABLED`。

本機開發推播伺服器要用金鑰時，執行 `npm run vapid:dev > push-worker/.dev.vars` 產生一組**只給本機測試**的金鑰（公鑰、私鑰一起覆寫），不要用正式私鑰；`.dev.vars`、`.env*`、`*.pem`、`*.key`、私鑰備份檔都已列在 `.gitignore`。

## 處理步驟

### 推播金鑰換新（定期或懷疑外洩時）

**在要上線前、`main` 分支上做**：推播伺服器一換金鑰，網站就要盡快拿到新公鑰，中間這段時間推播收不到。

1. 專案根目錄執行 `npm run vapid:rotate`，先看會做哪些事；確定後執行 `npm run vapid:rotate -- --yes`。腳本會：
   - 檢查在 `main` 分支、兩個設定檔沒有改到一半，不符合就不動任何東西
   - 產生新金鑰，私鑰存成桌面上的 `tomato-clock-推播私鑰-日期時間.txt`（只有你能讀，檔名精確到秒，不會蓋掉舊檔）
   - 新公鑰與新私鑰**一次**部署到推播伺服器（私鑰經由只有你能讀的暫存檔交給 wrangler，部署完立刻刪除，不會出現在畫面或指令參數）
   - **部署成功才**把新公鑰寫進 `push-worker/wrangler.jsonc` 與 `src/core/pushConfig.ts`；部署失敗時線上完全沒變，畫面會說明可以刪掉哪個備份檔
2. **馬上** commit 並把網站推上線。App 打開時發現訂閱用的是舊金鑰，會自動重新訂閱，使用者不用做任何事。
3. 打開備份檔，把私鑰存進密碼管理器，**刪掉備份檔**（桌面如果有同步到 iCloud 或 Time Machine，私鑰會被帶走）。
4. 在上線紀錄記一段「推播金鑰換新」。

### 推播私鑰遺失（例如 Worker 被刪、換 Cloudflare 帳號）

- 有密碼管理器的備份：`cd push-worker`，`npx wrangler secret put VAPID_PRIVATE_KEY`，貼上私鑰。
- 沒有備份：照「換新」步驟做，App 會自動重新訂閱。

### 推播私鑰外洩（貼到聊天、被 commit、出現在截圖）

1. 立刻照「換新」步驟做（舊私鑰就算被拿到，也只能對「用舊公鑰訂閱」的手機發推播，換新後全部失效）。
2. 如果是被 commit 進 Git：換新就夠了，不需要改寫 Git 歷史（舊私鑰已經沒用）。

### 電腦遺失或 wrangler 授權外洩

1. 到 Cloudflare 後台：My Profile → Access Management → Connected Applications，移除 Wrangler。
2. 新電腦上重新 `npx wrangler login`。

### 緊急止血：推播伺服器被灌請求

1. `push-worker/wrangler.jsonc` 把 `"PUSH_ENABLED": "true"` 改成 `"false"`，`cd push-worker`，`npx wrangler deploy`。
2. 伺服器之後對排程、取消一律回 503「推播暫停服務」，不碰 Durable Object；網站計時與畫面上的提醒照常，設定裡會顯示「推播暫停服務中」。
3. 查完原因再改回 `"true"` 並部署。

## 你要在網頁後台確認的設定（都是免費功能）

| 地方 | 設定 | 為什麼 |
|---|---|---|
| GitHub repo → Settings → Advanced Security | 開啟 Secret scanning 與 Push protection | push 時發現金鑰會直接擋下 |
| GitHub 帳號 → Settings → Billing | 確認是 Free、沒有付款方式 | 0 成本守則 1 |
| Cloudflare → Workers & Pages → Plans | 確認是 Free | 0 成本守則 1 |
| Cloudflare → Manage Account → Billing | 確認沒有付款方式 | 0 成本守則 1 |
| Cloudflare → My Profile → Access Management | 只保留需要的 Connected Applications | 減少授權外洩的風險 |
