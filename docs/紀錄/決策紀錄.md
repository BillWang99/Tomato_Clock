# 決策紀錄

一件事一段，格式：日期／決定／理由／影響哪份規格。只追加、不修改。

## 2026-10-23 導入 bstack

- 決定：專案導入 bstack 開發守門工具，文件依四層結構管理。
- 理由：快速交付的同時，確保每次更新資料安全、程式結構清楚。
- 影響：全部規格文件新增「功能清單」一節。

## 2026-10-23 像素蕃茄鐘第一版的技術取捨

- 決定：Vite + Vue 3 + TypeScript；不使用 Vue Router、Pinia、Element Plus、axios。狀態放 composable，計時邏輯寫成純函式放 `src/core/`。
- 理由：只有一個頁面、沒有後端 API，路由與 HTTP 套件用不到；元件庫的外觀會和像素風格衝突，按鈕等元件自己畫。計時正確性是唯一的高風險，獨立成純函式才能用假時鐘完整測試。
- 決定：中文像素字型用 Fusion Pixel Font（OFL），從官方 release 下載後只保留介面用到的字（約 19 KB）；npm 上的 @fontsource 版本只有拉丁字母，不能用。
- 決定：色盤用 Sweetie 16；計時數字自己畫 5×7 點陣字。
- 影響：規格/蕃茄鐘.md

## 2026-10-23 時長改成秒、時間鍵盤、PWA

- 決定：時長由分鐘改存秒數（範圍 00:01～99:59），讀到 v0.1.0 的分鐘欄位自動乘 60；今日統計也改存秒數。不另外回寫舊欄位。
- 理由：使用者要能設到秒（例如 50:30）。舊資料只要讀得進來就不會遺失；回寫舊欄位只為了退版，退版機率低，先不做（見規格「退版注意」）。
- 決定：時間輸入用自製的像素數字鍵盤（微波爐式輸入），不用手機系統鍵盤；點中央大數字或設定裡的時間都會打開。
- 理由：系統鍵盤的樣式和像素風格不搭，iOS 的數字鍵盤也沒有「分:秒」的格式；自製鍵盤可加快捷鍵（5／15／25／50 分）。
- 決定：PWA 用 vite-plugin-pwa（generateSW、autoUpdate），沿用原本的 manifest。
- 理由：自動產生預先快取清單與更新流程，比手寫 Service Worker 不容易漏檔；新版在下次打開時生效，不會在計時中途重新整理。
- 影響：規格/蕃茄鐘.md

## 2026-10-24 鎖螢幕推播的實作取捨

- 決定：推播加密套件用 `@block65/webcrypto-web-push` 2.0，不用一開始選的 `@pushforge/builder`。
- 理由：測試發現 pushforge 送的是舊的 `aesgcm` 格式；Apple 推播服務只收標準的 `aes128gcm`（RFC 8291）＋`vapid`（RFC 8292），block65 2.0 正好是這兩種，而且一樣只用 Web Crypto、能在 Cloudflare Worker 跑。
- 決定：推播伺服器放在同一個 repo 的 `push-worker/`，自己的 package.json 與測試（Cloudflare 的 vitest 外掛，在本機模擬的 Workers 環境跑），手動部署，不放進網站的 GitHub Actions。
- 理由：網站與伺服器部署節奏不同，伺服器很少改；分開部署也避免網站每次更新都要 Cloudflare 的登入憑證。
- 決定：伺服器只對已知推播服務的網址發請求、通知文字由伺服器產生。
- 理由：這是不用登入的公開 API，不限制的話可能被拿來對任意網址發請求或發廣告通知。
- 影響：規格/蕃茄鐘.md（鎖螢幕推播）

## 2026-10-24 金鑰與外部服務管理的取捨

- 決定：repo 維持 public；秘密只放服務商的秘密欄位（Cloudflare Worker secret）與使用者的密碼管理器，repo 只放清冊不放值。
- 理由：0 成本。public repo 的 Pages、Actions、Secret scanning 都免費；改 private 需要 GitHub Pro。秘密不在 repo 裡，public 也不影響安全。
- 決定：推播伺服器繼續從使用者電腦手動部署，不把 Cloudflare 金鑰放進 GitHub。
- 理由：伺服器很少改；少一個秘密就少一份外洩風險。
- 決定：換金鑰後由 App 自動比對訂閱的公鑰並重新訂閱，取代計劃原本寫的「使用者手動關掉再打開推播」。
- 理由：使用者變多時不可能要求每個人重開；自動處理零操作成本。
- 決定：換金鑰腳本限制在 main 分支、公私鑰用 `wrangler deploy --var --secrets-file` 一次部署、成功才改設定檔。
- 理由：審查發現分步驟執行時中途失敗會讓公私鑰對不上、推播悄悄失效；同日也發生在 feature 分支誤執行換金鑰（見上線紀錄 v0.6.0）。
- 影響：規格/外部服務與金鑰.md、規格/蕃茄鐘.md

## 2026-10-24 PWA 更新改成先問使用者

- 決定：Service Worker 由「背景自動換新、下次打開生效」改成「有新版先在畫面上方提示，使用者按『立即更新』才切換」，並在回到 App 與每小時自動檢查。
- 理由：主畫面的 App 常常一直留在背景不會重新打開，自動模式下使用者可能很久都還在用舊版；先問使用者也避免在計時途中突然重新載入。
- 影響：規格/蕃茄鐘.md（PWA）
