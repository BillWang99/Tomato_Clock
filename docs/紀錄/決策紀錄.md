# 決策紀錄

一件事一段，格式：日期／決定／理由／影響哪份規格。只追加、不修改。

## 2026-10-23 導入 bstack

- 決定：專案導入 bstack 開發守門工具，文件依四層結構管理。
- 理由：快速交付的同時，確保每次更新資料安全、程式結構清楚。
- 影響：全部規格文件新增「功能清單」一節。

## 2026-10-23 像素蕃茄鐘第一版的技術取捨

- 決定：Vite + Vue 3 + TypeScript；不使用 Vue Router、Pinia、Element Plus、axios。狀態放 composable，計時邏輯寫成純函式放 `src/core/`。
- 理由：只有一個頁面、沒有後端 API，路由與 HTTP 套件用不到；元件庫的外觀會和像素風格衝突，按鈕等元件自己畫。計時正確性是唯一的高風險，獨立成純函式才能用假時鐘完整測試。
- 決定：中文像素字型用 Fusion Pixel Font（OFL），從官方 release 下載後只保留介面用到的字（約 19 KB）；npm 上的 @fontsource 版本只有拉丁字母，不能用。
- 決定：色盤用 Sweetie 16；計時數字自己畫 5×7 點陣字。
- 影響：規格/蕃茄鐘.md

## 2026-10-23 時長改成秒、時間鍵盤、PWA

- 決定：時長由分鐘改存秒數（範圍 00:01～99:59），讀到 v0.1.0 的分鐘欄位自動乘 60；今日統計也改存秒數。不另外回寫舊欄位。
- 理由：使用者要能設到秒（例如 50:30）。舊資料只要讀得進來就不會遺失；回寫舊欄位只為了退版，退版機率低，先不做（見規格「退版注意」）。
- 決定：時間輸入用自製的像素數字鍵盤（微波爐式輸入），不用手機系統鍵盤；點中央大數字或設定裡的時間都會打開。
- 理由：系統鍵盤的樣式和像素風格不搭，iOS 的數字鍵盤也沒有「分:秒」的格式；自製鍵盤可加快捷鍵（5／15／25／50 分）。
- 決定：PWA 用 vite-plugin-pwa（generateSW、autoUpdate），沿用原本的 manifest。
- 理由：自動產生預先快取清單與更新流程，比手寫 Service Worker 不容易漏檔；新版在下次打開時生效，不會在計時中途重新整理。
- 影響：規格/蕃茄鐘.md
